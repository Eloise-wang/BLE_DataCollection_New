# 下位机需求设计文档（ZKFJ BLE DataCollection）

## 1. 目标与范围

- 目标：采集压力/温度/液位与电池电量，通过 BLE（Wireless UART）实现实时上报与历史回收；采集数据落盘到外置 NOR Flash（LittleFS）。
- 范围：设备侧任务划分、数据格式、协议交互、LED 行为、异常处理与调试开关。

## 2. 系统架构概览

- BLE：基于 NXP Wireless UART Profile，负责连接、notify 发送与 write 接收。
- 协议：自定义轻量帧协议（命令帧/数据帧/状态帧），带 CRC16 校验。
- 采集：ADC（温度/PT1000、压力）、CAN(J1939 解码 GCU1：液位与接入状态)、电池百分比（SDK Battery Service + 设备侧状态上报）。
- 存储：LittleFS 挂载在外置 NOR Flash，按任务目录存储数据与日志。
- RTOS：FreeRTOS 多任务 + 队列 + 事件组。

## 3. 任务与线程模型

- Protocol 任务
  - 功能：接收命令帧，参数校验，立刻回 ACK；历史回收触发数据发送；输出串口调试（可编译开关）。
- UART 命令接收任务
  - 功能：从 UART 读入十六进制文本，换行触发解析为二进制帧，喂给协议解析器（用于调试/工装）。
- Sensor 采集任务
  - 功能：按 period\_ms 定时采样；采样数据入队（供存储任务）；实时上报记录（数据帧）；更新剩余条数；触发采样指示灯 pulse。
- Storage 存储任务
  - 功能：从队列取记录写入 LittleFS；写入前创建任务目录与 meta；对挂载失败进行退避重试。
- LED 任务
  - 功能：启动自检四灯全亮一次；BLE 连接指示；采样 pulse 闪烁；采集完成常亮；历史回收发送时点亮发送灯；低电量报警灯闪烁。
- Watchdog 任务
  - 功能：周期喂狗；启动时输出/记录复位原因（看门狗复位标记）。

## 4. 采集数据与单位

### 4.1 实时采集物理量

- 压力：MPa（内部存储为 kPa，uint16）
- 温度：℃（内部存储为 0.01℃，int16）
- 液位：L（uint16；未接入用 0xFFFF 表示 -1L）

### 4.2 精度策略

- 温度与压力的浮点转整型采用四舍五入，避免直接截断导致的系统性偏差。
- 时间戳计算考虑系统毫秒计数回绕（>49 天），避免 elapsed 溢出错误。

## 5. 记录结构（sensor\_record\_t）

- 记录以 packed 小端序写入/上报，字段如下：
  - timestamp\_s(u32) + timestamp\_ms(u16)
  - temperature\_centi\_c(i16)
  - pressure\_kpa(u16)
  - liquid\_level(u16)（0xFFFF 表示 -1L）
  - remaining\_count(u32)
  - liquid\_access\_state(u8)
  - status(u8)（bit 标记：传感器错误/CAN 错误/存储错误/液位未接入）

## 6. 协议（帧类型与命令）

### 6.1 帧类型

- 命令帧：SOF=0xA5，字段：CMD/LEN/PAYLOAD/CRC16
- ACK 帧：SOF=0xA5，CMD=REQ\_CMD+0x80，LEN=1，PAYLOAD=STATUS
- 数据帧：SOF=0x5A，字段：payload\_len(u16)/task\_id/offset/total\_bytes/data/CRC16
- 状态帧：SOF=0x5B，字段：payload\_len(u16)/task\_id/event\_bits/battery/reserved/CRC16

### 6.2 命令集合（Host->Device）

- 0x01 SELFTEST：payload=task\_id(u64)；采样一次并走实时上报/存储链路。
- 0x02 START\_COLLECT：payload=task\_id(u64)+start\_s(u32)+duration\_s(u32)+period\_ms(u32)；开启采集，计算 total/remaining。
- 0x03 STOP\_COLLECT：payload=task\_id(u64)；停止采集。
- 0x04 REQUEST\_HISTORY：payload=task\_id(u64)+offset(u32)+max\_bytes(u16)；从 offset 开始持续发送到 total\_bytes 结束（连接断开则停止）。
- 0x05 CLEAR\_TASK：payload=task\_id(u64)+mode(u8)
  - mode=0：删除指定任务目录（安全删除文件）
  - mode!=0：格式化 LittleFS（清空所有任务数据）

### 6.3 状态位（event\_bits）

- bit0：COLLECT\_RUNNING
- bit1：STORAGE\_READY
- bit2：QUEUE\_DROPPED
- bit3：COLLECT\_DONE
- bit4：BLE\_CONNECTED
- bit5：HISTORY\_SENDING
- bit6：COLLECTION\_PULSE

## 7. LED 需求落地

- 启动自检：LED 初始化后四灯全亮固定时长，然后恢复正常状态。
- BLE\_LED：连接亮，断开灭。
- Collection\_LED：采样瞬间短闪；采集完成常亮；非采集灭。
- Send\_LED：历史回收发送窗口常亮；其余灭。
- Electricity\_LED：电量 <20% 闪烁报警。

## 8. 串口打印与调试开关

- 串口输出统一英文，避免终端编码问题。
- BSP UART 打印支持编译开关：BSP\_UART\_PRINT\_ENABLE（发布版可关闭所有 Print）。
- 采集任务的高频调试输出受 BSP\_UART\_PRINT\_ENABLE 控制，避免影响实时性。

## 9. 存储设计（LittleFS）

- 任务目录：task\_%016llX/
  - meta.bin：任务元数据（task\_id/开始时间/采样周期/持续时间/record\_size/version）
  - data.bin：按记录追加
  - sys.log：系统日志（可选）
- 删除指定任务：删除 data/meta/log，再删除目录。
- 清空所有任务：格式化文件系统（BSP\_FS\_Format）。

## 10. 异常与健壮性策略

- CAN 处理每次循环限制最大帧数，避免广播风暴导致任务饿死。
- 存储初始化失败采用退避重试，避免异常时 CPU 空转。
- 看门狗：固定周期喂狗，启动时输出复位原因，必要时清除 sticky 标志位。
