# 测试步骤（下位机固件 + 协议联调）

本文用于现场/实验室快速验证固件功能是否完整，包含：
- 上电自检与 LED 行为
- BLE 连接与协议收发
- 采集/停止/进度剩余条数
- 历史回收（大数据）
- 清除任务/清空 Flash（LittleFS format）

## 0. 测试前准备
- 固件：烧录最新固件，确保串口打印开启（编译宏 `BSP_UART_PRINT_ENABLE=1`）。
- 工具（二选一即可）：
  - BLE 调试工具：能写入特征、订阅 notify、收字节流并保存（PC/手机均可）。
  - 串口：115200（若你工程设置不同，以工程配置为准），用于观察调试日志与故障定位。
- 协议关键约定：
  - 命令帧 SOF=0xA5
  - ACK 帧 SOF=0xA5，CMD=REQ_CMD+0x80
  - 数据帧 SOF=0x5A
  - 状态帧 SOF=0x5B
  - CRC：CRC-16/CCITT-FALSE（poly=0x1021, init=0xFFFF）
  - 多字节字段均为小端序

## 1. 上电自检（LED）
### 1.1 预期现象
- 初始化完成后，四个 LED 同时点亮一次，然后恢复正常逻辑。

### 1.2 异常定位
- 若四灯不全亮：检查 GPIO/LED 驱动初始化、硬件焊接。

## 2. BLE 连接与状态心跳
### 2.1 步骤
1) 手机/PC 扫描设备，连接。
2) 订阅 notify（Wireless UART RX/Notify 特征）。

### 2.2 预期现象
- BLE 连接成功后：
  - BLE_LED 常亮
  - 周期性收到状态帧 `0x5B ...`（约 5 秒一次）

### 2.3 断开验证
1) 主动断开连接或远离设备。
2) 预期：BLE_LED 熄灭；设备不应持续高频发送导致耗电异常。

## 3. 协议命令测试（建议顺序）

说明：
- 以下命令示例使用固定 task_id=0x1122334455667788（payload 小端：`88 77 66 55 44 33 22 11`）。
- 若你要换 task_id，只改 payload 中 8 字节即可，CRC 需要随之重算。
- 下面示例的 CRC 已按当前固件算法计算，可直接用于测试。

### 3.1 SELFTEST（0x01）
用途：快速验证协议收发 + 采样链路是否通。

命令（Host->Device）：
```
A5 01 08 88 77 66 55 44 33 22 11 6D 67
```

预期：
- 收到 ACK（Device->Host）：
  - `A5 81 01 00 ...`（STATUS=0 表示 OK）
- 随后收到 0x5A 数据帧（实时记录），串口可见采样日志（若开启）。

### 3.2 START_COLLECT（0x02）
用途：验证按周期采集、remaining_count、采集 LED 逻辑、存储写入。

示例：start_s=1700000000，duration_s=10，period_ms=1000（共采集 10 次）

命令：
```
A5 02 14 88 77 66 55 44 33 22 11 00 F1 53 65 0A 00 00 00 E8 03 00 00 32 15
```

预期：
- ACK：`A5 82 01 00 97 AA`
- 采集过程中：
  - Collection_LED 采样瞬间闪烁（pulse）
  - 持续收到实时数据帧 0x5A（每秒 1 次）
  - 每条记录 remaining_count 递减，最终到 0
- 采集结束：
  - COLLECT_DONE 事件位置 1（状态帧 event_bits 可见）
  - Collection_LED 进入常亮（表示采集完成）

### 3.3 STOP_COLLECT（0x03）
用途：验证停止命令能立即终止采集。

命令（同 task_id）：
```
A5 03 08 88 77 66 55 44 33 22 11 8B 57
```

预期：
- 收到 ACK：`A5 83 01 00 ...`
- 之后不再有实时采样数据帧，Collection_LED 恢复非采集中状态（灭或仅完成常亮取决于当前状态机）。

备注：若你更换 task_id 或固件改动导致 CRC 不同，需要重算 CRC 后再发送。

## 4. 历史回收（0x04）
用途：验证大数据读取与 BLE 发送链路是否稳定。

### 4.1 请求历史（offset=0, max_bytes=200）
命令：
```
A5 04 0E 88 77 66 55 44 33 22 11 00 00 00 00 C8 00 9F CE
```

预期：
- ACK：`A5 84 01 00 ...`
- 随后连续收到多个数据帧 `0x5A`，直到传输完成。
- 发送过程中 Send_LED 常亮（HISTORY_SENDING 窗口）。

### 4.2 上位机验证要点（强烈建议）
- 对每个 `0x5A` 帧做 CRC 校验；失败的帧丢弃并记录次数。
- 以 `(task_id, offset)` 为索引，将 payload 中 data 追加到本地文件。
- 当 `offset + data_len == total_bytes` 时认为回收完成。
- 如遇断连：重新连接后可再次发同一条 `REQUEST_HISTORY` 从 offset=0 回收，或按你保存的文件长度从断点 offset 继续。

## 5. 清除任务（0x05）
### 5.1 清除指定任务（mode=0）
用途：验证删除单个任务目录，不影响其他任务。

命令格式：
- SOF A5
- CMD 05
- LEN 09
- PAYLOAD：task_id(u64) + mode(u8=0)
- CRC16：对 CMD+LEN+PAYLOAD 计算

说明：该条 CRC 与 task_id 强相关，建议测试时用“上位机脚本/工具”自动算 CRC。

预期：
- ACK OK
- 再次请求该 task_id 的历史：应返回 NOT_FOUND 或 STORAGE_ERROR（取决于实现）

### 5.2 清空所有任务（mode=1）
用途：验证 LittleFS format。

命令格式同上，mode=1。

预期：
- ACK OK
- 所有任务目录被清空；后续新任务可正常创建。

注意：按约束，采集中不允许执行清除操作。

## 6. 异常场景测试（建议至少做一次）
- CRC 错误命令帧：随便改一个字节但不改 CRC，预期设备拒绝并返回 CRC_ERROR（或不响应，取决于策略）。
- 大数据回收中断连：回收途中断开并重连，验证可重复回收或断点回收。
- 低电量：将电池压到阈值附近（或模拟），验证 Electricity_LED 闪烁。
