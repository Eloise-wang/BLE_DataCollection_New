# 上位机实现的完整方针（ZKFJ BLE DataCollection）

## 1. 目标

- 在 BLE（Wireless UART）链路上实现：设备发现/连接、命令下发、实时显示、历史回收、任务管理、日志与导出。
- 与下位机协议严格对齐：帧头、CRC、字节序、字段单位、状态位。

## 2. BLE 连接与收发

### 2.1 扫描/连接

- 扫描设备并连接（按约定设备名或服务 UUID 过滤）。
- 连接成功后订阅 notify/indicate，保证能接收设备上行字节流。

### 2.2 收发模型

- 下行：Write（Write Without Response / Write）发送二进制帧。
- 上行：Notify 收到的是字节流，需要做“帧边界”重组与 CRC 校验。

## 3. 协议说明

### 3.1 CRC16

- CRC-16/CCITT-FALSE：poly=0x1021, init=0xFFFF, refin=false, refout=false, xorout=0x0000
- 多字节字段均为 Little-Endian（小端序）。

### 3.2 帧格式（字段表）

#### A) 命令帧（Host->Device）

| 字段      |  长度 | 说明                        |
| ------- | --: | ------------------------- |
| SOF     |   1 | 0xA5                      |
| CMD     |   1 | 命令号                       |
| LEN     |   1 | payload 长度                |
| PAYLOAD | LEN | 负载                        |
| CRC16   |   2 | CRC16(CMD+LEN+PAYLOAD)，LE |

#### B) ACK 帧（Device->Host）

| 字段       | 长度 | 说明                            |
| -------- | -: | ----------------------------- |
| SOF      |  1 | 0xA5                          |
| CMD\_ACK |  1 | CMD+0x80                      |
| LEN      |  1 | 0x01                          |
| STATUS   |  1 | 状态码                           |
| CRC16    |  2 | CRC16(CMD\_ACK+LEN+STATUS)，LE |

#### C) 数据帧（Device->Host）

| 字段           | 长度 | 说明                             |
| ------------ | -: | ------------------------------ |
| SOF          |  1 | 0x5A                           |
| payload\_len |  2 | u16 LE                         |
| task\_id     |  8 | u64 LE                         |
| offset       |  4 | u32 LE                         |
| total\_bytes |  4 | u32 LE                         |
| data         |  N | N = payload\_len - 16          |
| CRC16        |  2 | CRC16(payload\_len+payload)，LE |

#### D) 状态帧（Device->Host）

| 字段               | 长度 | 说明                             |
| ---------------- | -: | ------------------------------ |
| SOF              |  1 | 0x5B                           |
| payload\_len     |  2 | u16 LE（固定 14）                  |
| task\_id         |  8 | u64 LE                         |
| event\_bits      |  4 | u32 LE                         |
| battery\_percent |  1 | 0\~100                         |
| reserved         |  1 | 0                              |
| CRC16            |  2 | CRC16(payload\_len+payload)，LE |

### 3.3 命令定义（字段表）

|  CMD | 名称               | payload                                                      |
| ---: | ---------------- | ------------------------------------------------------------ |
| 0x01 | SELFTEST         | task\_id(u64)                                                |
| 0x02 | START\_COLLECT   | task\_id(u64)+start\_s(u32)+duration\_s(u32)+period\_ms(u32) |
| 0x03 | STOP\_COLLECT    | task\_id(u64)                                                |
| 0x04 | REQUEST\_HISTORY | task\_id(u64)+offset(u32)+max\_bytes(u16)                    |
| 0x05 | CLEAR\_TASK      | task\_id(u64)+mode(u8)                                       |

STATUS 定义：

- 0x00 OK
- 0x01 CRC\_ERROR
- 0x02 LEN\_ERROR
- 0x03 CMD\_UNSUPPORTED
- 0x04 PARAM\_ERROR
- 0x05 BUSY
- 0x06 NOT\_FOUND
- 0x07 STORAGE\_ERROR

### 3.4 采样记录结构（18 bytes，小端，packed）

| 字段                    | 类型  | 单位/说明                |
| --------------------- | --- | -------------------- |
| timestamp\_s          | u32 | 秒                    |
| timestamp\_ms         | u16 | 毫秒                   |
| temperature\_centi\_c | i16 | 0.01℃（显示时除以 100）     |
| pressure\_kpa         | u16 | kPa（显示 MPa 时除以 1000） |
| liquid\_level         | u16 | L（0xFFFF 表示 -1L）     |
| remaining\_count      | u32 | 剩余采样条数               |
| liquid\_access\_state | u8  | 液位接入状态（来自 CAN）       |
| status                | u8  | 状态位（见下）              |

record.status 位定义：

- bit0 0x01 SENSOR\_ERROR
- bit1 0x02 CAN\_ERROR
- bit2 0x04 STORAGE\_ERROR
- bit3 0x08 LIQUID\_OFFLINE
- event\_bits 每一位含义（对应 task\_manager.h）
  - bit0 0x00000001 ：COLLECT\_RUNNING（正在采集）
  - bit1 0x00000002 ：STORAGE\_READY（存储会话已建立）
  - bit2 0x00000004 ：QUEUE\_DROPPED（传感器队列丢包/背压）
  - bit3 0x00000008 ：COLLECT\_DONE（采集完成）
  - bit4 0x00000010 ：BLE\_CONNECTED（BLE已连接）
  - bit5 0x00000020 ：HISTORY\_SENDING（正在回收发送）
  - bit6 0x00000040 ：COLLECTION\_PULSE（采样脉冲/闪灯用）

## 4. 示例 Hex 报文（可用作联调用例）

说明：示例 task\_id=0x1122334455667788（payload 中小端为 88 77 66 55 44 33 22 11）

### 4.1 SELFTEST

```
A5 /01 /08 /88 77 66 55 44 33 22 11 /6D 67
```

### 4.2 START\_COLLECT（start\_s=1700000000, duration\_s=10, period\_ms=1000）

```
A5 /02 /14 /88 77 66 55 44 33 22 11 /00 F1 53 65 0A 00 00 00 E8 03 00 00 32 15
```

ACK(OK)：

```
A5 82 01 00 97 AA
```

### 4.3 REQUEST\_HISTORY（offset=0, max\_bytes=200）

```
A5 04 0E 88 77 66 55 44 33 22 11 00 00 00 00 C8 00 9F CE
```

### 4.4 数据帧（历史数据第 1 包：total\_bytes=18，仅 1 条记录）

```
5A 22 00 88 77 66 55 44 33 22 11 00 00 00 00 12 00 00 00 01 F1 53 65 F4 01 E6 09 39 30 64 00 00 00 00 00 01 00 E9 F9
```

### 4.5 实时数据帧

```
 实时数据帧本质上也是 0x5A 数据帧 ，和 0x04 回收用的帧格式一致，只是 total_bytes 固定填 0 ，表示“实时流”（不是回收文件）。

- 发送入口： PROTO_SendRealtimeRecord
  - offset = seq * record_size （seq 每采一次加 1）
  - total_bytes = 0
  - data = sensor_record_t （18 字节，见 app_global.h ）
- 帧格式（SOF=0x5A）： PROTO_DataBuildFrame
  - 5A + payload_len(u16LE) + task_id(u64LE) + offset(u32LE) + total_bytes(u32LE=0) + data(record) + CRC16(u16LE)
- 一帧里面 就是 1 条记录 （每次采样发送一次），record 的字段就是：
  - timestamp_s/u32 、 timestamp_ms/u16 、 temperature_centi_c/i16 、 pressure_kpa/u16 、 liquid_level/u16 、 remaining_count/u32 、 liquid_access_state/u8 、 status/u8
```

### 4.6 状态帧

```
5B /0E 00 /88 77 66 55 44 33 22 11 /18 00 00 00 /64/ 00 /88 21
```

```
帧格式（Device→Host，0x5B）
- SOF： 5B （1字节）
- payload_len： 0E 00 （u16 小端，固定 14）
- task_id：u64 小端（8字节）
- event_bits：u32 小端（4字节）
- battery_percent：u8（1字节，0~100）
- reserved：u8（1字节，固定 0）
- CRC16：u16 小端（2字节），对 payload_len(2B)+payload(14B) 计算（不含 SOF）
```

## 5. 上位机功能模块拆分（工程实现建议）

### 5.1 协议层（强制）

- ByteStream -> Frame：按 SOF(0xA5/0x5A/0x5B) 与长度字段重组完整帧。
- CRC 校验：失败丢弃该帧并记录统计。
- 解码：将 payload 映射为结构体（注意小端与 packed）。

### 5.2 采集控制（强制）

- Start：生成 task\_id（建议用时间戳+随机数，或 GUID 截断为 u64），发送 START\_COLLECT。
- Stop：发送 STOP\_COLLECT。
- Selftest：发送 SELFTEST（用于现场快速验证）。

### 5.3 实时显示（强制）

- 实时数据来自数据帧（task\_id/offset/total\_bytes/data）。
- 解析每条记录，显示压力(MPa)/温度(℃)/液位(L)、remaining\_count、状态位。

### 5.4 历史回收（强制）

- 收到 REQUEST\_HISTORY 的 ACK 后，持续接收数据帧直到 offset+len == total\_bytes。
- 将 data 追加写入本地文件（bin 或直接解析为 CSV）。
- 建议：以 task\_id 建目录保存（meta.json + data.bin + data.csv）。

### 5.5 任务管理（建议）

- 清指定任务：CLEAR\_TASK mode=0。
- 清所有任务：CLEAR\_TASK mode=1（高危操作，二次确认）。

### 5.6 诊断与日志（建议）

- 帧统计：CRC 错误次数、丢包次数（offset 不连续）、重连次数、平均吞吐。
- 导出：CSV/Excel（时间戳、物理量、状态位）。

## 6.CRC计算

CRC 计算总结（对应你这个工程的命令帧/数据帧）

#### 1) CRC 类型与参数（CRC16）

在该工程里，协议用的 CRC16 来自硬件 CRC 模块配置（见 bsp\_crc.c ）：

- 多项式： 0x1021
- 初值（seed）： 0xFFFF
- reflectIn： false
- reflectOut： false
- xorOut（complementChecksum）： false （等价于 xorOut=0）
- 输出宽度：16 bit
- 输出顺序： 发送时按小端放到帧尾 （CRC low byte 在前，high byte 在后）
  这就是常说的 CRC-16/CCITT-FALSE（init=0xFFFF） 这一类（无反射、无异或）。

#### 2) CRC 覆盖哪些字节？

##### 命令帧（SOF=0xA5）

CRC 计算输入是：

- CMD (1 byte) + LEN (1 byte) + PAYLOAD (LEN bytes)
  注意： 不包含帧头 SOF=0xA5 。

代码依据： proto\_frame.c 里校验时用的是 cmd+len+payload 。

##### 数据帧（SOF=0x5A）/ 状态帧（SOF=0x5B）

CRC 计算输入是：

- LEN(2 bytes, 小端) + PAYLOAD(payload\_len bytes)
  同样： 不包含 SOF（0x5A/0x5B） 。

代码依据： proto\_frame.c （ crc = crc16(\&out\[1], 2 + payload\_len) ）。

#### 3) 发送时 CRC 怎么放？

- CRC16 计算结果是 16bit： crc
- 帧尾附加两个字节： crc\_lo = crc & 0xFF ， crc\_hi = (crc >> 8) & 0xFF
- 也就是 小端 ： lo hi
  举例：如果算出来 CRC=0x29A8，则帧尾是： A8 29 。

#### 4) 一个最短可验证例子（ACK）

对 0x02 START\_COLLECT 的 OK ACK：

- ACK cmd = 0x02 + 0x80 = 0x82
- len=1
- status=0
  CRC 输入为： 82 01 00
  算出的 CRC=0xAA97 → 帧尾 97 AA
  完整 ACK 帧： A5 82 01 00 97 AA

如果你用上位机算 CRC，能和这个对上，就说明 CRC 实现方向没错。
