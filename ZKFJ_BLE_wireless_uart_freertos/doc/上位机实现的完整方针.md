# 上位机实现的完整方针（ZKFJ BLE DataCollection）

## 1. 目标
- 在 BLE（Wireless UART）链路上实现：设备发现/连接、命令下发、实时显示、历史回收、任务管理、日志与导出。
- 与下位机协议严格对齐：帧头、CRC、字节序、字段单位、状态位。

## 2. BLE 连接与收发
### 2.1 扫描/连接
- 扫描设备并连接（按约定设备名或服务 UUID 过滤）。
- 连接成功后订阅 notify/indicate，保证能接收设备上行字节流。

### 2.2 收发模型
- 下行：Write（Write Without Response / Write）发送二进制帧。
- 上行：Notify 收到的是字节流，需要做“帧边界”重组与 CRC 校验。

## 3. 协议说明
### 3.1 CRC16
- CRC-16/CCITT-FALSE：poly=0x1021, init=0xFFFF, refin=false, refout=false, xorout=0x0000
- 多字节字段均为 Little-Endian（小端序）。

### 3.2 帧格式（字段表）
#### A) 命令帧（Host->Device）
| 字段 | 长度 | 说明 |
|---|---:|---|
| SOF | 1 | 0xA5 |
| CMD | 1 | 命令号 |
| LEN | 1 | payload 长度 |
| PAYLOAD | LEN | 负载 |
| CRC16 | 2 | CRC16(CMD+LEN+PAYLOAD)，LE |

#### B) ACK 帧（Device->Host）
| 字段 | 长度 | 说明 |
|---|---:|---|
| SOF | 1 | 0xA5 |
| CMD_ACK | 1 | CMD+0x80 |
| LEN | 1 | 0x01 |
| STATUS | 1 | 状态码 |
| CRC16 | 2 | CRC16(CMD_ACK+LEN+STATUS)，LE |

#### C) 数据帧（Device->Host）
| 字段 | 长度 | 说明 |
|---|---:|---|
| SOF | 1 | 0x5A |
| payload_len | 2 | u16 LE |
| task_id | 8 | u64 LE |
| offset | 4 | u32 LE |
| total_bytes | 4 | u32 LE |
| data | N | N = payload_len - 16 |
| CRC16 | 2 | CRC16(payload_len+payload)，LE |

#### D) 状态帧（Device->Host）
| 字段 | 长度 | 说明 |
|---|---:|---|
| SOF | 1 | 0x5B |
| payload_len | 2 | u16 LE（固定 14） |
| task_id | 8 | u64 LE |
| event_bits | 4 | u32 LE |
| battery_percent | 1 | 0~100 |
| reserved | 1 | 0 |
| CRC16 | 2 | CRC16(payload_len+payload)，LE |

### 3.3 命令定义（字段表）
| CMD | 名称 | payload |
|---:|---|---|
| 0x01 | SELFTEST | task_id(u64) |
| 0x02 | START_COLLECT | task_id(u64)+start_s(u32)+duration_s(u32)+period_ms(u32) |
| 0x03 | STOP_COLLECT | task_id(u64) |
| 0x04 | REQUEST_HISTORY | task_id(u64)+offset(u32)+max_bytes(u16) |
| 0x05 | CLEAR_TASK | task_id(u64)+mode(u8) |

STATUS 定义：
- 0x00 OK
- 0x01 CRC_ERROR
- 0x02 LEN_ERROR
- 0x03 CMD_UNSUPPORTED
- 0x04 PARAM_ERROR
- 0x05 BUSY
- 0x06 NOT_FOUND
- 0x07 STORAGE_ERROR

### 3.4 采样记录结构（18 bytes，小端，packed）
| 字段 | 类型 | 单位/说明 |
|---|---|---|
| timestamp_s | u32 | 秒 |
| timestamp_ms | u16 | 毫秒 |
| temperature_centi_c | i16 | 0.01℃（显示时除以 100） |
| pressure_kpa | u16 | kPa（显示 MPa 时除以 1000） |
| liquid_level | u16 | L（0xFFFF 表示 -1L） |
| remaining_count | u32 | 剩余采样条数 |
| liquid_access_state | u8 | 液位接入状态（来自 CAN） |
| status | u8 | 状态位（见下） |

record.status 位定义：
- bit0 0x01 SENSOR_ERROR
- bit1 0x02 CAN_ERROR
- bit2 0x04 STORAGE_ERROR
- bit3 0x08 LIQUID_OFFLINE

event_bits 位定义：
- bit0 0x00000001 COLLECT_RUNNING
- bit1 0x00000002 STORAGE_READY
- bit2 0x00000004 QUEUE_DROPPED
- bit3 0x00000008 COLLECT_DONE
- bit4 0x00000010 BLE_CONNECTED
- bit5 0x00000020 HISTORY_SENDING
- bit6 0x00000040 COLLECTION_PULSE

## 4. 示例 Hex 报文（可用作联调用例）
说明：示例 task_id=0x1122334455667788（payload 中小端为 88 77 66 55 44 33 22 11）

```

### 4.2 START_COLLECT（start_s=1700000000, duration_s=10, period_ms=1000）
```

```
ACK(OK)：
```

```

```

```

```

```

```

## 5. 上位机功能模块拆分（工程实现建议）
### 5.1 协议层（强制）
- ByteStream -> Frame：按 SOF(0xA5/0x5A/0x5B) 与长度字段重组完整帧。
- CRC 校验：失败丢弃该帧并记录统计。
- 解码：将 payload 映射为结构体（注意小端与 packed）。

### 5.2 采集控制（强制）
- Start：生成 task_id（建议用时间戳+随机数，或 GUID 截断为 u64），发送 START_COLLECT。
- Stop：发送 STOP_COLLECT。
- Selftest：发送 SELFTEST（用于现场快速验证）。

### 5.3 实时显示（强制）
- 实时数据来自数据帧（task_id/offset/total_bytes/data）。
- 解析每条记录，显示压力(MPa)/温度(℃)/液位(L)、remaining_count、状态位。

### 5.4 历史回收（强制）
- 收到 REQUEST_HISTORY 的 ACK 后，持续接收数据帧直到 offset+len == total_bytes。
- 将 data 追加写入本地文件（bin 或直接解析为 CSV）。
- 建议：以 task_id 建目录保存（meta.json + data.bin + data.csv）。

### 5.5 任务管理（建议）
- 清指定任务：CLEAR_TASK mode=0。
- 清所有任务：CLEAR_TASK mode=1（高危操作，二次确认）。

### 5.6 诊断与日志（建议）
- 帧统计：CRC 错误次数、丢包次数（offset 不连续）、重连次数、平均吞吐。
- 导出：CSV/Excel（时间戳、物理量、状态位）。
